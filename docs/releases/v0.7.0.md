# Corral v0.7.0

These are the release notes for v0.7.0. They cover all changes from v0.6.0 to
v0.7.0.

The v0.6.0 tag (2026-08-06) did not get a GitHub Release. Thus these notes also
cover the changes that came after v0.6.0. There is no separate v0.6.0 page.

To publish this release, a maintainer tags the release commit and pushes the
tag. The `release.yml` workflow then creates the release with this file as
the body. It also attaches the signed binaries, their SBOMs and the Sigstore
bundles:

```sh
git tag -s v0.7.0 <commit>
git push upstream v0.7.0
```

## Highlights

### Virtual desktops (VDI)

- Pool members are now claimed with leases. Two users cannot get the same
  desktop at the same time (#244).
- Assigned desktops can use native USB redirection (#260).
- Corral now checks GPU and host device capacity before it creates a pool
  (#261).
- The self-service broker on persistent VM pools is Stable on KubeVirt. CI
  tests it end to end. It keeps the assignments of v0.6.0 (see
  [Upgrade from v0.6.0](../vdi.md#upgrade-from-v060)) (#69).

### Web dashboard

- A command palette, a tree filter and keyboard shortcuts (#369).
- Dashboard widgets that you can move and resize, with live usage charts
  (#370).
- A data grid for the inventory, which keeps its state (#373).
- Console workspaces and a multiview that you can resize (#372).
- Range selection in the tree, a tag and IP filter, arrow-key focus and more
  bulk actions (#374).
- Right-click context menus on tree rows and grid rows (#385).
- To migrate a VM, drag it onto a node (#384).
- A host-power hook, and an `aws-power` plugin for EC2 VM hosts (#351).
- A demo site that runs the dashboard in the browser through WebAssembly
  (#364).
- The dashboard shows only the backends that you configured. You can resize
  the sidebar (#294).

### Operations

- New `/healthz` and `/readyz` endpoints. The manifests and the runbook use
  them (#258).
- The `corral` catalog and VM lists can give JSON output (#251).
- The scheduled backup CronJob can run as a non-root user (#367).
- Web container images for more than one architecture (#225).
- The deploy manifests now collect the Prometheus metrics that Corral
  already gives (#278).

### QEMU and bootc

- QEMU VMs get UEFI firmware support. You can see a VM while Corral creates it
  (#333).
- QEMU VMs get VSOCK, TPM and diagnostic parity with the end-to-end tests
  for the tunaOS ISO.
- New `corral vmtest` command: a bootc VM tester for CI, with image layers,
  hooks and screenshots (#300).
- The bootc import does not pull a `localhost/` image. It also tells you when
  it runs in a nested container (#300).

### Move and export

- A Proxmox VE VM can be a move source. Incus can be a publish destination
  (#189).
- The scratch file for a move gets a random name that is difficult to guess
  (#314).

### Plugins and supply chain

- Marketplace v2 is now the minimum integrity level for plugins (#294).
- The CI job now publishes binaries for macOS. The installer verifies what
  it downloads (#315).
- `corral version` shows the release tag, not the most recent `plugins-<sha>`
  tag (#316).
- The workflows pin all GitHub Actions to a digest (#253).
- The TurnKey catalog entries use HTTPS and ISO URLs that work (#308).
- Scripts remove their temporary files. Logs do not go to an unsafe
  temporary path (#301, #323).

## Changes that can affect you

- Plugin installs now check a Sigstore signature and an SPDX SBOM
  attestation. An unsigned plugin does not install (#505). For an
  air-gapped install, set `CORRAL_SIGSTORE_TRUSTED_ROOT`.
- The `corral` binary is about 9 MB larger because it contains the
  Sigstore verifier.
- `corral create --context <proxmox>` now creates the VM on Proxmox VE.
  Before, it made a local QEMU VM (#493).
- `corral clone` now puts the clone in the namespace of the source VM
  (#564).
- Corral does not accept a VM name that contains `/`, `..` or NUL. Before, such a
  name could delete folders outside the VM folder (#497, #502).
- We removed old build files from the git history (#264). If you cloned
  the repository before this release, clone it again.

## Also in this release

### Security and supply chain

- CI signs the release binaries and the container image without keys
  (Sigstore), and attaches SPDX SBOMs (#584). `scripts/install.sh` checks
  the signature when `cosign` is installed. Set
  `CORRAL_REQUIRE_SIGNATURE=1` to make the signature check mandatory.
- `index.html` has integrity digests for all vendored scripts and styles
  (#504).
- The `corral-web` RBAC rule has only the verbs that the code uses (#459).

### Backends

- Commands for Incus and libvirt VMs (viewer, logs, restart, snapshots) now
  go to the correct backend (#489, #491).
- `corral context use` now applies to new Incus, libvirt and KubeVirt VMs
  (#490).
- Pause, migrate, scale, export and the new `corral tag` command go through
  the backend adapters (#595).
- VirtualBox: clone, CPU and memory change, OVA export and SSH (#586, #587,
  #590). vSphere: disk export (#589). XenServer and XCP-ng: XVA export
  (#591). Nutanix: tags and OVA export (#588, #596). These backends are
  Tier 3 (see [docs/enterprise-readiness.md](../enterprise-readiness.md)).

### VDI

- Self-service broker API (`/api/vdi/`, opt-in) (#227).
- Session records and conservative reclaim (#228).
- One-click connect from the web Desktops screen or `corral vdi connect`
  (#229).
- Pools of ephemeral desktops in containers (`corral vdi ct-pool`) (#230).

### bootc and CI boot gates

- `corral vmtest` has `--fail-marker`, `--karg`, `--filesystem` and UEFI
  boot (#546).
- Local builds of composefs images (#514).
- `corral create --bootc` and `corral bootc create` have `--karg` (#570).

### Observability

- Structured logs (`--log-level`, `--log-format`, `--log-file`). Logs
  remove secrets. The TUI writes its log to a file (#578).
- The web server gives each request an ID (`X-Request-ID`). The ID goes to
  the backend commands, peer requests and tasks (#579).
- The metric `corral_last_activity_timestamp_seconds` shows when a person
  last used the host (#355).

### Fixes

- `corral gc` no longer stops or deletes a VM with the same name in a
  different namespace (#538).
- `corral stop` on a local VM no longer kills an unrelated process. Before,
  this could occur when the PID file of swtpm was old (#540).
- A Windows guest with `--memory 16GB` now gets 16 GiB, not 16 MiB (#536).
- Backups without `--format` get the file extension of their real format
  (#533).
- Local VM creation from the web works again (#501).
- The config file has a lock across processes, and Corral reads the file
  again when it changes (#360).

### Internal

- New tests raise the coverage floor from 60.7% to 69.0% (#506).
- We split `pkg/web/server.go`, `app.js` and the TUI into smaller files and
  modules, with tests first (#503, #288, #305, #554).
- 27 places in the code still check for a backend name, down from 46.
  Each one has a reason in
  [docs/backend-parity.md](../backend-parity.md) (#214).

## Other changes

- Many dependency updates through Renovate, which include `golang.org/x/crypto`,
  `golang.org/x/net`, `go-webauthn` and `bubbletea`.
- More tests for the backend adapters, the plugin SDK, Incus, Proxmox, fleet
  selectors and the demo cluster. The test order is now random, and a ratchet
  keeps the coverage from going down.
- In demo mode, a theme change does not change your real configuration.
  The web server uses `XDG_CONFIG_HOME` (#388).
- All Markdown passes the check for Simplified Technical English (#356).

## Install

- Homebrew: `brew upgrade corral-vm`. The `release-brew.yml` workflow updates
  the formula in `tuna-os/homebrew-tap` when a maintainer publishes this release.
- Script: `scripts/install.sh`. It gets binaries from the `binaries` release,
  which CI updates on each push to `main`.
