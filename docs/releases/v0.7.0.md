# Corral v0.7.0

These are the release notes for v0.7.0. They cover all changes from v0.6.0 to
v0.7.0.

The v0.6.0 tag (2026-08-06) did not get a GitHub Release. Thus these notes also
cover the changes that came after v0.6.0. There is no separate v0.6.0 page.

To publish this release, a maintainer tags the release commit and uses this
file as the release body:

```sh
git tag -s v0.7.0 <commit>
git push upstream v0.7.0
gh release create v0.7.0 --title "Corral v0.7.0" --notes-file docs/releases/v0.7.0.md
```

## Highlights

### Virtual desktops (VDI)

- Pool members are now claimed with leases. Two users cannot get the same
  desktop at the same time (#244).
- Assigned desktops can use native USB redirection (#260).
- Corral now checks GPU and host device capacity before it creates a pool
  (#261).

### Web dashboard

- A command palette, a tree filter and keyboard shortcuts (#369).
- Dashboard widgets that you can move and resize, with live usage charts
  (#370).
- A data grid for the inventory, which keeps its state (#373).
- Console workspaces and a multiview that you can resize (#372).
- Range selection in the tree, a tag and IP filter, arrow-key focus and more
  bulk actions (#374).
- Right-click context menus on tree rows and grid rows (#385).
- To migrate a VM, drag it onto a node (#384).
- A host-power hook, and an `aws-power` plugin for EC2 VM hosts (#351).
- A demo site that runs the dashboard in the browser through WebAssembly
  (#364).
- The dashboard shows only the backends that you configured. You can resize
  the sidebar (#294).

### Operations

- New `/healthz` and `/readyz` endpoints. The manifests and the runbook use
  them (#258).
- The `corral` catalog and VM lists can give JSON output (#251).
- The scheduled backup CronJob can run as a non-root user (#367).
- Web container images for more than one architecture (#225).
- The deploy manifests now collect the Prometheus metrics that Corral
  already gives (#278).

### QEMU and bootc

- QEMU VMs get UEFI firmware support. You can see a VM while Corral creates it
  (#333).
- QEMU VMs get VSOCK, TPM and diagnostic parity with the end-to-end tests
  for the tunaOS ISO.
- New `corral vmtest` command: a bootc VM tester for CI, with image layers,
  hooks and screenshots (#300).
- The bootc import does not pull a `localhost/` image. It also tells you when
  it runs in a nested container (#300).

### Move and export

- A Proxmox VE VM can be a move source. Incus can be a publish destination
  (#189).
- The scratch file for a move gets a random name that is difficult to guess
  (#314).

### Plugins and supply chain

- Marketplace v2 is now the minimum integrity level for plugins (#294).
- The CI job now publishes binaries for macOS. The installer verifies what
  it downloads (#315).
- `corral version` shows the release tag, not the most recent `plugins-<sha>`
  tag (#316).
- The workflows pin all GitHub Actions to a digest (#253).
- The TurnKey catalog entries use HTTPS and ISO URLs that work (#308).
- Scripts remove their temporary files. Logs do not go to an unsafe
  temporary path (#301, #323).

## Other changes

- Many dependency updates through Renovate, which include `golang.org/x/crypto`,
  `golang.org/x/net`, `go-webauthn` and `bubbletea`.
- More tests for the backend adapters, the plugin SDK, Incus, Proxmox, fleet
  selectors and the demo cluster. The test order is now random, and a ratchet
  keeps the coverage from going down.
- In demo mode, a theme change does not change your real configuration.
  The web server uses `XDG_CONFIG_HOME` (#388).
- All Markdown passes the check for Simplified Technical English (#356).

## Install

- Homebrew: `brew upgrade corral-vm`. The `release-brew.yml` workflow updates
  the formula in `tuna-os/homebrew-tap` when a maintainer publishes this release.
- Script: `scripts/install.sh`. It gets binaries from the `binaries` release,
  which CI updates on each push to `main`.
